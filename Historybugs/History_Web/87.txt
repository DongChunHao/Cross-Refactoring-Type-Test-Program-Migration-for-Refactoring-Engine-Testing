/*

The destructuring is equivalent to `(cond ? callbackEventEvent.message : callbackEventEvent).text`.
After inlining, IDE produces `cond ? callbackEventEvent.message.text : callbackEventEvent.text`, which changes semantics:
it tries to read `.text` on each branch individually, instead of reading `.text` on the result of the ternary.
If one branch object does not have a `text` property, this introduces a runtime error that was not present before.

Expected behavior: Wrap the whole ternary expression in parentheses before accessing `.text`:

Underlying cause:
The variable inliner treats object destructuring `{text} = expr` as `expr.text`, but when `expr` is a ternary conditional expression, it fails to preserve the precedence and group the entire conditional as the receiver of the `.text` property access; instead it distributes the property access into each branch of the ternary.
