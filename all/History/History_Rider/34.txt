Observed failure: When running Extract Class on a static method, the refactoring UI incorrectly asks for an object reference/instance parameter for the new extracted class.
Since the source method is static, it does not depend on an instance of the original type, and the extracted class should not require an instance reference to be passed in.

Expected behavior:
If the source member is static and does not capture instance state from the containing class:
1. The Extract Class dialog should not prompt for an instance reference parameter.

Underlying cause:
The Extract Class refactoring’s dependency analysis treats all members uniformly, using the instance-member workflow even for static methods.
