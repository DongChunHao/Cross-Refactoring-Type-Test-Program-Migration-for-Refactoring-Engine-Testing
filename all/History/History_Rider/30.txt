/* Error Root Cause:
Observed failure:
When using "Extract Method into Class" refactoring and selecting an existing target class that already has a non‑parameterless constructor, Rider’s refactoring logic fails.
Symptoms:
1. The refactoring either errors out;
2. Or it tries to add a new parameterless constructor automatically;
3. Or it injects the extracted method’s captured state into the existing constructor incorrectly, causing compilation errors.

Expected behavior:
Rider needs to handle two scenarios:
1. If the existing class has a constructor that can accept the captured dependencies: reuse it, map captured variables to constructor arguments.
2. If the existing constructor signature conflicts / cannot accept the required captured state:
   - Offer to add an overloaded constructor for the new dependencies;
   - Or warn the user that the target class already has a parameterized constructor and cannot accept the extracted state.

Underlying cause:
The “Extract Method into Class” implementation assumes by default that it can add a parameterless constructor to the target class, or that it can append captured fields to a default constructor.
It does not properly check for existing parameterized constructors, and lacks logic to choose between overloading the constructor vs reusing an existing compatible one.
*/
